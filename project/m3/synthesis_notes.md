# Synthesis Notes and Scope Status

## 1. Synthesis Journey and Environment Setup
The synthesis process for the CNN MAC core was a comprehensive exercise in managing the OpenLane 2 toolchain within a WSL2 environment. Initially, the process was stalled because the `openlane` command was not recognized in the standard Ubuntu PATH. After diagnosing the environment, I identified an `openlane2` folder in my home directory. By navigating to this directory and initializing the environment using `nix-shell`, the necessary toolchains (including Yosys, OpenROAD, and Magic) were successfully activated. This transition from a standard environment to the Nix-managed environment was the primary hurdle in starting the synthesis flow.

## 2. OpenLane Run and Tool Quirks
Once the environment was activated, the synthesis flow was initiated using the custom `config.json` file. The tool successfully executed the entire flow, including Yosys for synthesis and OpenROAD for placement and routing.

However, extracting the results presented a challenge. Initial attempts to locate the timing reports using wildcards like `*setup.rpt` failed because OpenLane 2 generated files with specific corner names rather than generic names. Through recursive file searching (`find` and `grep`), I identified the final timing reports stored under `54-openroad-stapostpnr/max_ss_100C_1v60/max.rpt`. This experience highlighted the importance of understanding the hierarchical folder structure generated by the OpenLane 2 toolset during the physical design phase.

## 3. Synthesis Results and Critical Path
The design successfully passed all manufacturing checks:
* **DRC (Design Rule Check):** Passed
* **LVS (Layout vs. Schematic):** Passed
* **Antenna Check:** Passed

These results confirm that the Verilog code is synthesizable and meets the physical layout requirements. Regarding timing, the design encountered setup violations when constrained to a 10.0ns (100MHz) clock period. The critical path was traced to the logic path from input `s_axis_tdata[15]` to register `_1317_`. The path involves a significant sequence of logic gates, specifically a chain of buffers and compound AND-OR logic cells (`sky130_fd_sc_hd__a21oi_1`, `sky130_fd_sc_hd__a211o_1`, etc.). This timing violation is expected for an initial synthesis pass and confirms that the logic is functional but requires further optimization.

## 4. Scope Status and Milestone 4 Outlook
No reduction in project scope is necessary. The CNN core successfully synthesized, and the AXI4-Stream interface, which handles data flow, is fully integrated and functional.

For Milestone 4, the primary objective will be to optimize the identified critical path to meet the 100MHz timing constraint. Strategies will include:
1. **Pipelining:** Introducing additional flip-flop stages to break up the long chain of AND/OR/Buffer logic gates.
2. **Logic Restructuring:** Refactoring the RTL code in `compute_core.sv` to simplify the combinatorial logic between registers.
3. **Constraint Adjustment:** If timing constraints are overly aggressive for the current architecture, I will explore relaxing the clock period in `config.json` while maintaining performance benchmarks.

The current baseline is stable, and I am confident that these adjustments will yield a compliant and performant physical implementation in the final project phase.
